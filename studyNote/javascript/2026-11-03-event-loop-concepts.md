# 자바스크립트 이벤트 루프 개념 정리

> [!NOTE]
> JS 코드는 메인 스레드 하나에서 한 번에 하나씩만 실행되고, 네트워크 대기는 스레드 밖에서 일어나 끝나면 콜백이 대기열에 들어간다.

> [!WARNING]
> **헷갈린 점** · '동시에 된다'는 느낌은 대기 중에 스레드가 비어 다른 콜백이 번갈아 실행되기 때문이며, 오래 걸리는 동기 작업은 모두를 밀어낸다.

## 📖 자세히

### 한 줄 정의와 왜 필요한지
이벤트 루프(event loop)는 '실행할 코드가 끝나 스레드가 비면, 대기열(큐)에서 다음 콜백을 꺼내 실행'하는 반복 구조다. JS는 메인 스레드가 하나라서, 서버 응답을 기다리는 동안 멈추지 않도록 '기다림은 밖에 맡기고 결과가 오면 콜백으로 받는' 방식을 쓴다.

### 동작 원리
1. 현재 실행 중인 코드(콜 스택)가 끝까지 동기로 실행된다. 중간에 끼어들 수 없다.
2. `setTimeout`, ajax, 웹소켓 연결 같은 작업은 브라우저/런타임이 스레드 밖에서 처리하고 즉시 반환한다.
3. 작업이 끝나면 콜백이 대기열에 들어간다. 마이크로태스크(Promise `.then`, `await` 이후)는 일반 타이머 큐보다 먼저 비워진다.
4. 콜 스택이 비면 이벤트 루프가 대기열에서 하나를 꺼내 실행한다.

```text
[콜 스택] 초기화 코드 실행 -> 끝
   |  setTimeout(500) / ajax 요청만 등록하고 반환
[스레드 비움] 화면 그리기, 클릭 처리 가능
   |  네트워크 응답 도착 -> 콜백이 큐에 들어감
[콜 스택] 콜백 실행 -> 다음 요청 등록 -> 끝
```

### 구성 요소/용어 정리
| 용어 | 뜻 |
|---|---|
| 콜 스택 | 지금 실행 중인 함수들이 쌓이는 곳 |
| 태스크 큐 | 타이머, I/O 콜백이 기다리는 줄 |
| 마이크로태스크 큐 | Promise 콜백. 태스크보다 먼저 실행 |
| 블로킹 | 동기 작업이 스택을 오래 점유해 다른 콜백이 못 도는 상태 |

### 코드로 보기
```ts
// 실행 순서: sync -> microtask -> timeout
setTimeout(() => log.push('timeout'), 0); // 태스크 큐
Promise.resolve().then(() => log.push('microtask')); // 마이크로태스크 큐
log.push('sync'); // 지금 바로 실행
```

```ts
// 10ms 뒤 실행을 예약했지만, 동기 작업이 50ms 점유하면 그만큼 늦어진다
setTimeout(() => resolve(Date.now() - start), 10);
while (Date.now() - start < 50) {} // 스레드 점유
```

### 비교
| | 병렬(parallel) | 이벤트 루프의 동시성 |
|---|---|---|
| JS 코드 | 동시에 여러 개 실행 | 한 번에 하나, 대기 중에 번갈아 실행 |
| 대기(I/O) | - | 스레드 밖에서 처리 |

### 자주 하는 실수와 주의점
- 콜백 안에서 큰 반복문, 큰 DOM 조작, 동기 파일 처리를 하면 클릭, 화면 갱신, 소켓 메시지 처리가 모두 늦어진다.
- `setTimeout(fn, 500)`은 '500ms 뒤 정확히 실행'이 아니라 '최소 500ms 뒤, 스레드가 비면 실행'이다.
- 초기화 순서가 요청 응답 콜백 체인으로 이어지면, 그 사이에 사용자 이벤트 핸들러가 먼저 실행될 수 있다. 핸들러에서 아직 준비 안 된 객체(소켓 등)를 쓰는지 점검한다.

### 세션에서 나온 질문 정리
- Q. DOM 로드 때 UI 설정과 웹소켓 연결이 동시에 되나?
  A. 아니다. UI 설정 핸들러가 끝까지 동기로 실행된 뒤, 스레드가 비고 나서 예약된 타이머나 응답 콜백에서 연결이 시작된다.
- Q. 그럼 스레드를 계속 점유하나?
  A. 연결 요청 자체는 즉시 반환한다. 핸드셰이크 같은 대기는 스레드 밖에서 진행되고, 완료 이벤트만 콜백으로 온다.
- Q. 그런데 왜 동시에 도는 것처럼 보이나?
  A. 대기 중에 스레드가 비어 클릭, 렌더링, 메시지 처리가 번갈아 실행되기 때문이다.
